# 设备接入识别与阻断控制系统 — 总体框架设计与任务需求

> 面向家庭或小型办公网络的设备接入识别与阻断控制系统
> 技术栈:Python (Scapy + FastAPI) + React (Ant Design + Recharts) + SQLite
> 状态:已完成基线开发 + Tier 1~3 增强 + 被动指纹 / 时段控制 / QoS 限速,共 8 次迭代

---

## 一、项目概述

### 1.1 项目背景

随着物联网与移动设备的普及,家庭和小型办公网络中接入的设备越来越多。未经授权的设备(如蹭网设备、可疑终端)可能带来数据泄漏、内网渗透、带宽占用等安全风险。本项目设计并实现一个轻量级的"设备接入识别与阻断控制系统",通过主动扫描 + 被动监听的方式发现局域网内所有在线设备,建立设备画像,识别异常接入行为,并提供阻断与审计能力。

### 1.2 系统目标

1. **自动发现**:扫描局域网,识别所有在线设备并维护资产清单;被动 ARP 监听实时检测上线
2. **设备画像**:基于 IP/MAC/厂商 OUI/主机名/OS 推测 + TCP SYN 被动指纹 + DHCP 指纹多维识别
3. **智能分类**:白名单/黑名单/未知三态 + OUI 自动分类 + 规则引擎联动
4. **访问控制**:7 种阻断后端 + 定时阻断 + 上网时段限制 + 带宽 QoS 限速
5. **实时可视**:Dashboard 趋势图 + WebSocket 实时推送 + 设备详情抽屉
6. **审计追溯**:所有接入、告警、阻断、分类、限速操作完整落盘

### 1.3 适用场景

- 家庭无线网络的访客管理、儿童上网时段控制、带宽管理
- 小型办公网络的资产盘点与访问控制
- 实验室、教学场景的网络安全演示
- Linux 热点网关部署 (推荐); Windows 热点模式支持

## 二、总体框架设计

### 2.1 系统分层架构

| 层次 | 主要职责 | 关键技术 |
|------|----------|----------|
| 表示层 | 可视化展示、实时推送、用户交互、配置管理 | React 18 + Ant Design 5 + Recharts |
| 业务逻辑层 | 设备识别、风险判定、策略执行、流量采集、审计 | FastAPI + APScheduler + Pydantic |
| 数据层 | 设备资产、流量画像、告警、规则、审计持久化 | SQLite + SQLAlchemy 2.0 ORM |
| 采集层 | ARP/Nmap 发现、WiFi Deauth、流量抓包、主机名解析 | Scapy + python-nmap + psutil |

### 2.2 核心模块划分(12 模块)

**(1) 设备发现模块 (Discovery)**:ARP 扫描(广播 free ARP) + ICMP Ping + Nmap 后备。未装 Npcap 时自动降级到 Nmap。30s 周期调度,支持手动触发。

**(2) 设备指纹模块 (Fingerprint)**:OUI 厂商识别(manuf) + DNS/mDNS/NetBIOS 三重主机名解析 + TTL+OUI 启发式 OS 推测。**Tier 4 新增**:TCP SYN 被动指纹(18 条 p0f 风格签名:Windows/Linux/macOS/iOS/Android/Cisco/IoT) + DHCP 指纹(Option 60 Vendor Class + Option 12 Hostname)。

**(3) 设备登记模块 (Registry)**:白/黑/未知三态管理 + OUI 自动分类。知名厂商(Apple/Samsung/Xiaomi 等 15 家)设备首次发现自动归为白名单,减少人工审核。

**(4) 数据采集模块 (Telemetry)**:在线/离线状态跟踪(120s 阈值)、AccessLog 事件记录、WebSocket 实时广播、5s 轻量流量采样(pkt/bytes/top_ports/unique_dst_ips/unique_dst_ports 写入 DeviceTraffic 表)。**Tier 3+ 新增**:被动 ARP+Dhcp+TCP SYN 三合一监听器,设备一连网即实时检测上线并采集指纹,**无需等待扫描间隔**。

**(5) 流量画像模块 (Traffic)**:DeviceTraffic 表存储每次流量的包数、字节数、目的端口 Top5、目的 IP 数、目的端口数,支持按设备查询流量历史。

**(6) 风险判定模块 (Risk Engine)**:JSON DSL 规则引擎(支持 all/any 递归 + ==/!=/in/not_in/>/< / >=/<= 八类操作符,新增 is_new/flip_count_1min/unique_ips_5min/unique_ports_5min 上下文字段)。action=block 规则触发时自动调用阻断(blocked_by="auto")。

**(7) 阻断控制模块 (Blocker)**:七种后端可选:
- `deauth`:802.11 解除认证帧踢下线(WiFi 专属,需网卡支持帧注入)
- `arp`:双层 ARP 欺骗(L1 广播泛洪 + L2 请求嗅探即时应答)
- `route`:本机路由表黑洞(Windows route add / Linux ip route blackhole)
- `netsh`:Windows 防火墙按 IP 阻断
- `iptables`:Linux FORWARD 链按 MAC DROP
- `ssh_iptables`:SSH 远程调用 Linux 虚拟机 iptables(跨平台过渡方案)
- `none`:仅监控不阻断

支持定时阻断(duration_min 参数)、到期自动解除、阻断来源追踪(manual/schedule/auto)、WebSocket 广播阻断/解除事件。

**(8) 时段控制模块 (Scheduler)**:基于时间的上网访问控制。每设备可配置禁止上网时段(HH:MM-HH:MM),支持跨天(如 22:00-06:00)。调度器每轮扫描自动执行时段阻断/放行,仅影响 blocked_by="schedule" 的设备,**不动手动阻断**。

**(9) 带宽管理模块 (QoS)**:基于 Linux tc (HTB) 按设备 IP 限速。下行限速(egress class+filter) + 上行限速(ingress policing)。启动时自动恢复持久化的限速规则。非 Linux 平台返回明确错误。

**(10) 审计日志模块 (Audit)**:所有接入/告警/阻断/分类/配置变更经统一入口 write_audit() 落盘。后端导出脚本支持 CSV。

**(11) 实时推送模块 (WebSocket)**:ConnectionManager 管理连接池 + broadcast_sync() 同步包装。6 种事件类型:device.online / device.offline / alert.new / device.blocked / device.unblocked。前端 RealtimeBanner 组件实时弹通知,断线自动重连。

**(12) 可视化模块 (Dashboard)**:4 卡片实时统计(设备总数/在线/告警/阻断中) + 24h 趋势折线图(设备上线+告警双线) + Settings 可视化配置。设备详情页拆分为独立 Card:基本信息/阻断信息/上网时段/带宽限制。

### 2.3 数据流设计

1. **被动监听线程**持续嗅探 ARP/DHCP/TCP SYN → 实时检测上线 + 补全 OS 指纹
2. **扫描线程**周期调用 Discovery → 得 (IP, MAC) 列表(主动兜底)
3. **Fingerprint** 补全厂商、OS(TCP SYN > DHCP > TTL/OUI 优先级)、主机名
4. **Registry** 比对资产表 → 新设备自动按 OUI 分类 → 标记在线
5. **Telemetry** 更新 last_seen、写 AccessLog、广播 device.online
6. **Traffic Sampler** 5s 抓包 → 写 DeviceTraffic 表(含端口/IP 统计)
7. **Risk Engine** 加载启用规则 → 逐设备评估 → 生成告警 → 广播 alert.new
8. action=block 规则触发 → **Blocker** 自动阻断(blocked_by="auto") → 广播 device.blocked
9. 定时阻断到期 → **Scheduler** 自动 unblock(blocked_until) → 广播 device.unblocked
10. 上网时段检查 → **Scheduler** 按 block_schedule 自动阻断/放行(blocked_by="schedule")
11. 带宽 QoS 限速 → 手动触发或预留自动规则 → tc 规则生效
12. **Audit** 统一落盘所有操作
13. **Dashboard** 通过 REST API + WebSocket 拉取/推送实时展示

### 2.4 部署架构

**推荐部署:**
- **Linux 网关模式** (推荐):树莓派/迷你 PC 运行,开启 WiFi 热点(hostapd/nmcli),设备连接 Linux 热点 → Linux 做网关 → iptables 阻断 + tc QoS 限速全部生效
- **Windows 热点模式**:PC 开启 Windows 移动热点 → netsh/route 阻断生效,QoS 不可用
- **SSH 远程阻断**:Windows 后端 + Linux VM iptables(过渡方案,不推荐)
- **单机开发模式**:直接运行,以管理员权限启动

## 五、核心数据模型(6 张表)

### 5.1 device 表(设备资产)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| mac | TEXT UNIQUE | MAC 地址(主标识,小写存储) |
| ip | TEXT INDEXED | 当前 IPv4/IPv6 |
| hostname | TEXT NULLABLE | 主机名(DNS/mDNS/NetBIOS 解析) |
| vendor | TEXT NULLABLE | OUI 厂商(manuf 库) |
| os_guess | TEXT NULLABLE | 操作系统猜测(TTL+OUI+主机名启发式) |
| category | TEXT DEFAULT "unknown" | white / black / unknown |
| risk_level | INTEGER DEFAULT 0 | 0=低 1=中 2=高 3=严重(只升不降,ack 后手动重置) |
| status | TEXT DEFAULT "offline" | online / offline / blocked |
| first_seen | DATETIME | 首次发现时间 |
| last_seen | DATETIME INDEXED | 最近在线时间 |
| blocked_until | DATETIME NULLABLE | 定时阻断到期时间(到期自动 unblock) |
| block_schedule_start | VARCHAR(5) NULLABLE | 禁止上网时段起始 (HH:MM) |
| block_schedule_end | VARCHAR(5) NULLABLE | 禁止上网时段结束 (HH:MM,支持跨天) |
| blocked_by | VARCHAR(16) NULLABLE | 阻断来源: manual / schedule / auto |
| qos_down_kbps | INTEGER NULLABLE | 下载限速 (kbps) |
| qos_up_kbps | INTEGER NULLABLE | 上传限速 (kbps) |
| note | TEXT NULLABLE | 备注 |

### 5.3 alert 表(告警)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| device_id | FK→device.id INDEXED | |
| rule_id | FK→rule.id NULLABLE | 触发规则(含 relationship) |
| level | INTEGER DEFAULT 0 | 0~3 风险等级 |
| message | TEXT | 告警详情 |
| status | TEXT DEFAULT "open" | open / acknowledged / closed |

### 5.4 rule 表(规则)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| name | TEXT UNIQUE | 规则名称 |
| description | TEXT NULLABLE | 规则说明 |
| condition_json | TEXT | JSON DSL 条件 |
| action | TEXT | alert / block |
| level | INTEGER DEFAULT 1 | 规则风险等级 0~3 |
| enabled | BOOLEAN DEFAULT true | 启用/禁用 |

**condition_json 语法:**

```json
// 简单条件
{"field": "category", "op": "==", "value": "black"}

// 组合条件(all/any 递归)
{"all": [
  {"field": "category", "op": "==", "value": "unknown"},
  {"field": "hour", "op": "in", "value": [0,1,2,3,4,5,23]}
]}

// 支持操作符:== != in not_in > < >= <=
// 支持字段:mac ip category vendor hour status is_new flip_count_1min unique_ips_5min unique_ports_5min
```

**默认规则(5 条):**
1. 未知设备夜间接入(23~6 点) → alert, level=2
2. 黑名单设备上线 → block, level=3 (触发后自动阻断)
3. 陌生设备首次接入 → alert, level=2 (category=unknown AND is_new=true)
4. 设备频繁上下线 → alert, level=2 (1分钟内 flip_count >= 6—可能是攻击或故障)
5. 设备端口扫描行为 → block, level=3 (5分钟内访问>=30个端口或>=15个IP)

## 七、阻断方案详解

### 7.1 后端对比

| 后端 | 平台 | 原理 | 跨设备阻断 | 适用场景 |
|------|------|------|-----------|----------|
| **netsh** | Windows | Windows 防火墙按 IP 拦截转发流量 | ✅ PC 做网关时 | PC 热点模式(推荐) |
| **route** | 跨平台 | 本机路由黑洞 | ❌ 仅本机↔目标 | 同级客户端场景 |
| **deauth** | 跨平台 | 802.11 解除认证帧踢下线 | ✅ 需网卡支持帧注入 | WiFi 场景(部分网卡不行) |
| **arp** | 跨平台 | L1广播泛洪+L2请求嗅探 | ✅ 但 iOS 有防护 | Android/Windows/Linux 设备 |
| **iptables** | Linux | FORWARD 链按 MAC DROP | ✅ 本机做网关时 | Linux 网关模式(推荐) |
| **ssh_iptables** | 跨平台 | SSH 远程调用 Linux VM iptables | ✅ VM 在流量路径时 | Windows→Linux VM 过渡方案 |
| **none** | 跨平台 | 不阻断 | - | 仅监控模式 |

### 7.2 推荐部署拓扑

**Linux 网关模式 (推荐):**
```
互联网 → Linux(hostapd热点+后端运行) → 所有设备连接Linux热点
                ↓
    iptables阻断 + tc QoS + 被动ARP/DHCP/TCP监听全部生效
```

**Windows 热点模式:**
```
手机热点(互联网) → PC(WiFi连接+开启移动热点) → iPad/其他设备(连接PC热点)
                                                  ↓
                                        所有流量必经PC → netsh/route阻断生效
```

### 7.3 上网时段控制

每设备可设置禁止上网的时间窗口(如 22:00-06:00),支持跨天。调度器每轮扫描自动检查:
- 在当前窗口内 + 设备在线 → 自动阻断(blocked_by="schedule")
- 离开窗口 + 被 schedule 阻断 → 自动放行
- 手动阻断(blocked_by="manual")或自动阻断(blocked_by="auto")不会被时段逻辑影响

### 7.4 带宽 QoS 限速

基于 Linux tc (HTB) 实现,按设备 IP 精确限速:
- 下载限速:egress class + u32 filter 匹配 dst IP
- 上传限速:ingress policing 匹配 src IP 丢包
- 仅 Linux 有效,非 Linux 平台返回 HTTP 400
- 重启后自动恢复持久化的限速规则

### 7.5 定时阻断

block API 支持 `duration_min` 参数,例如 `POST /blocker/1/block?duration_min=60` 阻断 60 分钟后自动解除。Scheduler 每轮扫描(30s)检查 `blocked_until` 过期设备并自动调用 `unblock_device`。`blocked_by` 字段追踪阻断来源(manual/schedule/auto),防止不同来源的阻断互相干扰。

## 十、风险点与注意事项

**权限与合规**:ARP 扫描和阻断需管理员权限(Windows:以管理员运行;Linux:root/CAP_NET_RAW/CAP_NET_ADMIN)。在他人网络中使用须取得授权。

**ARP 阻断的局限**:iOS/macOS 会丢弃免费 ARP,单层 ARP 欺骗无效。L2 嗅探+即时应答可部分绕过,但不保证 100%。对付苹果设备推荐 deauth 或 PC 做网关+netsh。

**WiFi Deauth 依赖网卡**:部分笔记本 WiFi 网卡(特别是 Intel 系列)不支持 802.11 原始帧注入,deauth 后端在部分设备上不可用。

**MAC 伪造规避**:攻击者可伪造白名单设备 MAC,系统通过记录 MAC 出现在异常时段/TTL 不一致等模式辅助发现。

**扫描频率**:默认 30s,可配置 10~3600s。过于频繁会产生网络噪声。

**前后端时钟**:所有时间戳使用服务器本地时间(北京时间)存储,前端统一格式化为 YYYY-MM-DD HH:mm:ss。

**流量采样的隐私考量**:只抓 IP 层包头,不触碰载荷内容。top_ports 仅记录端口号,不记录具体通信内容。

**QoS 限速的平台依赖**:带宽限速基于 Linux tc 命令,仅 Linux 网关模式可用。Windows/Mac 上调用 API 会返回 HTTP 400 明确错误提示。

**被动 TCP SYN 指纹的局限**:签名库覆盖主流 OS,但内核定制/虚拟机/容器可能产生非标准签名导致未能识别。DHCP 指纹作为补充提高覆盖率。
