# 设备接入识别与阻断控制系统 — 总体框架设计与任务需求

> 面向家庭或小型办公网络的设备接入识别与阻断控制系统
> 技术栈:Python (Scapy + FastAPI) + React (Ant Design + Recharts) + SQLite
> 状态:已完成基线开发 + Tier 1~3 增强,共 5 次迭代

---

## 一、项目概述

### 1.1 项目背景

随着物联网与移动设备的普及,家庭和小型办公网络中接入的设备越来越多。未经授权的设备(如蹭网设备、可疑终端)可能带来数据泄漏、内网渗透、带宽占用等安全风险。本项目设计并实现一个轻量级的"设备接入识别与阻断控制系统",通过主动扫描 + 被动监听的方式发现局域网内所有在线设备,建立设备画像,识别异常接入行为,并提供阻断与审计能力。

### 1.2 系统目标

1. **自动发现**:扫描局域网,识别所有在线设备并维护资产清单
2. **设备画像**:基于 IP/MAC/厂商 OUI/主机名/OS 推测等多维信息建立身份画像
3. **智能分类**:白名单/黑名单/未知三态 + OUI 自动分类 + 规则引擎联动
4. **逻辑阻断**:支持 deauth / ARP 欺骗 / route / netsh / iptables 六种阻断后端,适配不同网络拓扑
5. **实时可视**:Dashboard 趋势图 + WebSocket 实时推送 + 设备详情抽屉
6. **审计追溯**:所有接入、告警、阻断、分类操作完整落盘

### 1.3 适用场景

- 家庭无线网络的访客管理与防蹭网
- 小型办公网络的资产盘点与访问控制
- 实验室、教学场景的网络安全演示
- Windows 热点 / Linux 网关均支持

## 二、总体框架设计

### 2.1 系统分层架构

| 层次 | 主要职责 | 关键技术 |
|------|----------|----------|
| 表示层 | 可视化展示、实时推送、用户交互、配置管理 | React 18 + Ant Design 5 + Recharts |
| 业务逻辑层 | 设备识别、风险判定、策略执行、流量采集、审计 | FastAPI + APScheduler + Pydantic |
| 数据层 | 设备资产、流量画像、告警、规则、审计持久化 | SQLite + SQLAlchemy 2.0 ORM |
| 采集层 | ARP/Nmap 发现、WiFi Deauth、流量抓包、主机名解析 | Scapy + python-nmap + psutil |

### 2.2 核心模块划分(10 模块)

**(1) 设备发现模块 (Discovery)**:ARP 扫描(广播 free ARP) + ICMP Ping + Nmap 后备。未装 Npcap 时自动降级到 Nmap。30s 周期调度,支持手动触发。

**(2) 设备指纹模块 (Fingerprint)**:OUI 厂商识别(manuf) + DNS 反向解析 + NetBIOS(nbtstat/nmblookup) + mDNS(avahi-resolve) 三重主机名解析 + TTL+OUI 启发式 OS 推测。

**(3) 设备登记模块 (Registry)**:白/黑/未知三态管理 + OUI 自动分类。知名厂商(Apple/Samsung/Xiaomi 等 15 家)设备首次发现自动归为白名单,减少人工审核。

**(4) 数据采集模块 (Telemetry)**:在线/离线状态跟踪(120s 阈值)、AccessLog 事件记录、WebSocket 实时广播、5s 轻量流量采样(pkt/bytes/top_ports 写入 DeviceTraffic 表)。

**(5) 流量画像模块 (Traffic)**:DeviceTraffic 表存储每次流量的包数、字节数、目的端口 Top5,支持按设备查询流量历史。

**(6) 风险判定模块 (Risk Engine)**:JSON DSL 规则引擎(支持 all/any 递归 + ==/!=/in/not_in/>/< 六类操作符)。规则外提为参数避免 N+1 查询。action=block 规则触发时自动调用阻断。

**(7) 阻断控制模块 (Blocker)**:六种后端可选:
- `deauth`:802.11 解除认证帧踢下线(WiFi 专属,需网卡支持帧注入)
- `arp`:双层 ARP 欺骗(L1 广播泛洪 + L2 请求嗅探即时应答),对抗 iOS 免费 ARP 丢弃
- `route`:本机路由表黑洞(Windows route add / Linux ip route blackhole)
- `netsh`:Windows 防火墙按 IP 阻断
- `iptables`:Linux FORWARD 链按 MAC DROP
- `none`:仅监控不阻断

支持定时阻断(duration_min 参数)、到期自动解除、WebSocket 广播阻断/解除事件。

**(8) 审计日志模块 (Audit)**:所有接入/告警/阻断/分类/配置变更经统一入口 write_audit() 落盘。后端导出脚本支持 CSV。

**(9) 实时推送模块 (WebSocket)**:ConnectionManager 管理连接池 + broadcast_sync() 同步包装。6 种事件类型:device.online / device.offline / alert.new / device.blocked / device.unblocked。前端 RealtimeBanner 组件实时弹通知,断线自动重连。

**(10) 可视化模块 (Dashboard)**:4 卡片实时统计(设备总数/在线/告警/阻断中) + 24h 趋势折线图(设备上线+告警双线) + Settings 可视化配置。

### 2.3 数据流设计

1. **扫描线程**周期调用 Discovery → 得 (IP, MAC) 列表
2. **Fingerprint** 补全厂商、OS、主机名
3. **Registry** 比对资产表 → 新设备自动按 OUI 分类 → 标记在线
4. **Telemetry** 更新 last_seen、写 AccessLog、广播 device.online
5. **Traffic Sampler** 5s 抓包 → 写 DeviceTraffic 表
6. **Risk Engine** 加载启用规则 → 逐设备评估 → 生成告警 → 广播 alert.new
7. action=block 规则触发 → **Blocker** 自动阻断 → 广播 device.blocked
8. 定时阻断到期 → **Scheduler** 自动 unblock → 广播 device.unblocked
9. **Audit** 统一落盘所有操作
10. **Dashboard** 通过 REST API + WebSocket 拉取/推送实时展示

### 2.4 部署架构

**推荐部署:**
- **Windows 热点模式**:PC 开启 Windows 移动热点,iPad/其他设备连接 PC 热点 → PC 做网关 → netsh/route 阻断生效
- **Linux 网关模式**:树莓派/迷你 PC 运行,需 CAP_NET_RAW/CAP_NET_ADMIN 能力
- **单机开发模式**:直接运行,以管理员权限启动

## 五、核心数据模型(6 张表)

### 5.1 device 表(设备资产)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| mac | TEXT UNIQUE | MAC 地址(主标识,小写存储) |
| ip | TEXT INDEXED | 当前 IPv4/IPv6 |
| hostname | TEXT NULLABLE | 主机名(DNS/mDNS/NetBIOS 解析) |
| vendor | TEXT NULLABLE | OUI 厂商(manuf 库) |
| os_guess | TEXT NULLABLE | 操作系统猜测(TTL+OUI+主机名启发式) |
| category | TEXT DEFAULT "unknown" | white / black / unknown |
| risk_level | INTEGER DEFAULT 0 | 0=低 1=中 2=高 3=严重(只升不降,ack 后手动重置) |
| status | TEXT DEFAULT "offline" | online / offline / blocked |
| first_seen | DATETIME | 首次发现时间 |
| last_seen | DATETIME INDEXED | 最近在线时间 |
| blocked_until | DATETIME NULLABLE | 定时阻断到期时间(到期自动 unblock) |
| note | TEXT NULLABLE | 备注 |

### 5.2 access_log 表(接入历史)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| device_id | FK→device.id | |
| event_type | TEXT | online / offline / ip_change |
| ip | TEXT | 事件时的 IP |
| timestamp | DATETIME INDEXED | 事件时间 |

### 5.3 alert 表(告警)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| device_id | FK→device.id INDEXED | |
| rule_id | FK→rule.id NULLABLE | 触发规则(含 relationship) |
| level | INTEGER DEFAULT 0 | 0~3 风险等级 |
| message | TEXT | 告警详情 |
| status | TEXT DEFAULT "open" | open / acknowledged / closed |
| created_at | DATETIME INDEXED | 告警时间 |

### 5.4 rule 表(规则)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| name | TEXT UNIQUE | 规则名称 |
| description | TEXT NULLABLE | 规则说明 |
| condition_json | TEXT | JSON DSL 条件 |
| action | TEXT | alert / block |
| level | INTEGER DEFAULT 1 | 规则风险等级 0~3 |
| enabled | BOOLEAN DEFAULT true | 启用/禁用 |

**condition_json 语法:**

```json
// 简单条件
{"field": "category", "op": "==", "value": "black"}

// 组合条件(all/any 递归)
{"all": [
  {"field": "category", "op": "==", "value": "unknown"},
  {"field": "hour", "op": "in", "value": [0,1,2,3,4,5,23]}
]}

// 支持操作符:== != in not_in > <
// 支持字段:mac ip category vendor hour status
```

**默认规则(2 条):**
1. 未知设备夜间接入(23~6 点) → alert,level=2
2. 黑名单设备上线 → block,level=3(触发后自动阻断)

### 5.5 audit_log 表(审计)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| actor | TEXT | system / user |
| action | TEXT INDEXED | device_discovered / block / unblock / set_category:white / set_category:black |
| target_device_id | FK→device.id NULLABLE | |
| reason | TEXT NULLABLE | 操作原因 |
| timestamp | DATETIME INDEXED | 操作时间 |

### 5.6 device_traffic 表(流量画像)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | |
| device_id | FK→device.id INDEXED | |
| pkt_in | BIGINT | 入站包数 |
| pkt_out | BIGINT | 出站包数 |
| bytes_in | BIGINT | 入站字节 |
| bytes_out | BIGINT | 出站字节 |
| top_ports | TEXT NULLABLE | JSON 数组,Top5 端口 |
| sample_at | DATETIME INDEXED | 采样时间 |

## 六、API 设计

统一前缀 `/api/v1`。以下列出完整路由表。

### 6.1 设备 `/devices`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/devices` | 列表(支持 ?category=&status= 筛选,DB 端 ORDER BY last_seen DESC) |
| GET | `/devices/{id}` | 详情(含 alert_count, access_count) |
| GET | `/devices/{id}/history` | 接入历史(?limit=50) |
| GET | `/devices/{id}/alerts` | 关联告警 |
| GET | `/devices/{id}/audit` | 关联操作记录 |
| POST | `/devices/{id}/whitelist` | 设为白名单 |
| POST | `/devices/{id}/blacklist` | 设为黑名单 |

### 6.2 扫描 `/scan`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/scan/trigger` | 手动触发一次扫描(后台任务) |
| GET | `/scan/status` | 扫描状态 |

### 6.3 告警 `/alerts` + 规则 `/rules`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/alerts` | 列表(?status=&device_id= 筛选,ORDER BY created_at DESC) |
| POST | `/alerts/{id}/ack` | 确认告警 |
| POST | `/alerts/{id}/close` | 关闭告警 |
| GET | `/rules` | 规则列表(ORDER BY name) |
| POST | `/rules` | 创建规则(含 JSON 校验) |
| PUT | `/rules/{id}` | 更新规则 |
| DELETE | `/rules/{id}` | 删除规则 |
| POST | `/rules/{id}/toggle` | 启用/禁用切换 |

### 6.4 阻断 `/blocker`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/blocker/{id}/block` | 阻断(?reason=&gateway_ip=&duration_min=) |
| POST | `/blocker/{id}/unblock` | 解除阻断(?reason=) |
| GET | `/blocker/active` | 当前活跃阻断列表 |

### 6.5 审计 `/audit`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/audit` | 审计列表(?limit=200,按 ID DESC) |

### 6.6 系统设置 `/settings`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/settings` | 读取当前配置(blocker_backend/scan_interval/lan_cidr 等) |
| PUT | `/settings` | 更新 .env 文件 + 立即更新运行时配置 |

### 6.7 统计 `/stats`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/stats/overview` | 全局统计(设备/在线/阻断/告警/白名单/黑名单/总流量) |
| GET | `/stats/timeline` | 24h 趋势(每小时设备上线+告警数) |
| GET | `/stats/traffic/{device_id}` | 设备流量历史(?limit=24) |

### 6.8 WebSocket `/ws`

| 方法 | 路径 | 说明 |
|------|------|------|
| WS | `/ws/realtime` | 实时事件流 |

**事件类型:**

| type | data | 触发时机 |
|------|------|----------|
| `device.online` | {id, ip, mac} | 设备上线 |

| `device.blocked` | {id, ip, mac, reason} | 设备被阻断 |
| `device.unblocked` | {id, ip, mac, reason} | 阻断解除 |

## 七、阻断方案详解

### 7.1 后端对比

| 后端 | 平台 | 原理 | 跨设备阻断 | 适用场景 |
|------|------|------|-----------|----------|
| **netsh** | Windows | Windows 防火墙按 IP 拦截转发流量 | ✅ PC 做网关时 | PC 热点模式(推荐) |
| **route** | 跨平台 | 本机路由黑洞 | ❌ 仅本机↔目标 | 同级客户端场景 |
| **deauth** | 跨平台 | 802.11 解除认证帧踢下线 | ✅ 需网卡支持帧注入 | WiFi 场景(部分网卡不行) |
| **arp** | 跨平台 | L1广播泛洪+L2请求嗅探 | ✅ 但 iOS 有防护 | Android/Windows/Linux 设备 |
| **iptables** | Linux | FORWARD 链按 MAC DROP | ✅ 本机做网关时 | Linux 网关模式 |
| **none** | 跨平台 | 不阻断 | - | 仅监控模式 |

### 7.2 推荐部署拓扑

```
手机热点(互联网) → PC(WiFi连接+开启移动热点) → iPad/其他设备(连接PC热点)
                                                  ↓
                                        所有流量必经PC → netsh/route阻断生效
```

这是 Windows 上对付苹果设备最有效的拓扑。PC 做网关后,iPad 无法绕过 PC 的防火墙。

### 7.3 定时阻断

block API 支持 `duration_min` 参数,例如 `POST /blocker/1/block?duration_min=60` 阻断 60 分钟后自动解除。Scheduler 每轮扫描(30s)检查 `blocked_until` 过期设备并自动调用 `unblock_device`。

## 十、风险点与注意事项

**权限与合规**:ARP 扫描和阻断需管理员权限(Windows:以管理员运行;Linux:root/CAP_NET_RAW/CAP_NET_ADMIN)。在他人网络中使用须取得授权。

**ARP 阻断的局限**:iOS/macOS 会丢弃免费 ARP,单层 ARP 欺骗无效。L2 嗅探+即时应答可部分绕过,但不保证 100%。对付苹果设备推荐 deauth 或 PC 做网关+netsh。

**WiFi Deauth 依赖网卡**:部分笔记本 WiFi 网卡(特别是 Intel 系列)不支持 802.11 原始帧注入,deauth 后端在部分设备上不可用。

**MAC 伪造规避**:攻击者可伪造白名单设备 MAC,系统通过记录 MAC 出现在异常时段/TTL 不一致等模式辅助发现。

**扫描频率**:默认 30s,可配置 10~3600s。过于频繁会产生网络噪声。

**前后端时钟**:所有时间戳 UTC 存储,展示时按浏览器时区转换。

**流量采样的隐私考量**:只抓 IP 层包头,不触碰载荷内容。top_ports 仅记录端口号,不记录具体通信内容。
